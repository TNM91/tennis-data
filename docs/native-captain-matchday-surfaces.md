# Native captain match preparation

Captain home and Match Center share a fixture card with opponent, date, start time and courts. Missing logistics remain explicit. Selected-player availability stays separate from shared court confirmations, and readiness remains unchecked until the captain requests a current snapshot.

Readiness metrics, the next decision and supporting tools use the native navy, ice and lime surfaces. Team planning actions sit in a responsive group. Match cards separate the date from the opponent, while private, shared and final lineup progress keeps its existing text with supporting state accents. Match-day counts show only explicit arrival updates.

This is a presentation change. It adds no endpoints, permissions, signing inputs, dependencies or artwork and preserves the existing fixture, version and stale-response checks. Chromium and WebKit fixtures cover narrow and enlarged-text layouts, step navigation, retained search, keyboard focus return, pending delivery, explicit arrivals and a fixture switch during a pending read. Fixtures isolate all external services; physical iPhone and VoiceOver checks remain separate.
