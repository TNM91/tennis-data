# Native chat unread indicators

Chats shows a lime unread-message badge on the main tab and each team in the inbox. Totals include General and named rooms, with 100 displayed as 99+. Muted conversations remain unread in the inbox; existing mute/block settings still suppress external notifications. Reading the message list advances its existing saved checkpoint. Opening a team or changing tabs alone does not clear unread messages.

The verified-account GET `/api/mobile/chats/unread` returns only owner-scoped counts. It reuses the installed service-only `native_team_chat_rooms` list aggregate, which verifies current membership/removals, excludes the reader, deleted posts and blocked authors, and bounds each room count. No schema, grants, room creation or message bodies are involved. Duplicate links are collapsed; more than 50 links or any unavailable aggregate fails closed. There are at most four concurrent room reads, normally one per linked team.

One foreground subscription to the existing RLS-protected, content-free `team_chat_signals` table invalidates counts. Bursts coalesce through the existing two-second chat reconciliation window. The subscription stops in the background and refreshes on resume/reconnect. Confirmed local read checkpoints and explicit inbox refresh also refresh counts. Same-account token refresh preserves the counter; account changes clear it immediately and discard old responses. There is no idle polling or persisted unread cache. A failed count hides the badge instead of reporting zero.

External iPhone alerts reuse the existing approved APNs registration and delivery path. Chats now includes the same opt-in control as My Lab. Users enable Chat notifications and allow iOS notifications; team/room mute and block settings remain enforced. APNs uses generic message text and a recipient-bound room destination. No new Apple permission/capability, credential, paid provider, invitations or automatic message sends are added. Physical device delivery still needs user acceptance after installing the build.

The device control is labeled **Turn off chat notifications** because it revokes that iPhone's registration for both team and Coach delivery. The separate Coach account choice stays saved when device notifications are turned off. Re-enabling the device never changes that choice.

A foreground push receipt for the currently registered, signed-in recipient invalidates unread counts for a valid Team or Coach destination. Receipt bursts coalesce, with at least two seconds between refresh starts and at most one active refresh. Both document visibility and native App state must be active; background, malformed, foreign-account, disabled-device and stale-owner work is discarded. There is no idle polling or automatic retry after failure. The receipt handler itself does not navigate, load conversation bodies, acknowledge reads or rebuild open forms and message drafts. An eligible open Coach view can react to those verified counts by loading its selected conversation while caught up; search and earlier history retain explicit loading, and the existing foreground/end-visible guard controls read acknowledgements. See `docs/native-coach-complete-integration.md` for the bounded automatic-update policy. Notification taps retain their existing separate access-checked navigation flow. Physical APNs receipt and presentation remain separate from simulated bridge checks.

The top-right account action now uses a settings gear. The profile action remains the person icon. The native scoreboard uses the versioned v3 court master documented in `public/brand/docs/MANIFEST.txt`; existing approved logos and app icons retain their original bytes.

## Inbox catch-up

Chats adds a local team/league search and All/Unread filters. Under each team, General and named rooms with unread messages have their own count and direct open action. The destination always includes the exact team, league, flight and optional room ID; the existing room loader checks current access again. The team card continues to open General. Room names are rendered as text, with no message previews or media requests.

The same count response now projects General's count and at most twelve named-room IDs, names and counts per team. It reuses the already-loaded RPC result: no additional database reads, polling, membership writes or permission changes. Older clients ignore the additive fields; newer clients accept the previous count-only response and omit direct room shortcuts until details are available. Muted rooms remain in unread results.

Search and filters stay in the current Chats view when opening/returning from a room or refreshing teams. They reset when that view is disposed, including account changes; they are never saved to device storage. Live counts update existing room controls without rebuilding the search field or resetting its caret. If a focused room becomes read, focus returns to its team; if the Unread filter hides that team, focus returns to the filter. Unknown/failed counts say unavailable rather than caught up. Reading or acknowledging a room retains the existing read-position protections and does not clear another room's count.

Synthetic phone checks cover both browser engines at 320/390 pixels with enlarged text, exact scopes for duplicate team names, named/General navigation, local-only filters, retained state, count failures, removed shortcuts, revoked room access and account changes. The production bundle is checked with all external HTTP and WebSocket traffic blocked. Physical iPhone/VoiceOver acceptance remains separate. No real message, alert, membership or read-position write is used for automated QA.

## iPhone app icon

For an iPhone already opted into chat notifications, a complete verified count response also updates the app icon with the combined team and Coach unread count, capped at 100. iPhone Settings controls whether badges are displayed. This uses Apple's existing [badge API](https://developer.apple.com/documentation/usernotifications/unusernotificationcenter/setbadgecount(_:withcompletionhandler:)); it requests no permission and registers no additional device. A complete zero clears the icon; a partial, missing or foreign-account response preserves the last confirmed icon count. Unknown counts cannot falsely clear it. Muted conversations retain the same unread meaning as the Chats tab.

Badge updates share the existing registration/logout queue, coalesce rapid changes and skip confirmed duplicates. Only the native helper's explicit `applied: true` confirms a count. An iPhone-settings refusal or a failed write leaves the applied value unknown, so a fresh verified unread snapshot can try again even when its number matches a previous attempt. Refusal creates no warning or permission prompt, and neither refusal nor failure starts an automatic retry. A badge write finishes before logout or notification-off cleanup; queued old-account writes cannot restore it afterward. Failures retain login, messaging and notification controls. No count, owner or message is added to device storage.

The icon reflects the most recently confirmed foreground count and remains on the Home Screen after leaving the app. Eligible background APNs alerts also carry the server's complete unread-count snapshot; see [background chat badges](mobile-chat-badges.md) for its service-only aggregate and delivery limits. This foreground confirmation fix adds no polling, database query, grant, credential or Apple capability and does not change background delivery. Browser/native-bridge fixtures verify the code path; physical Home Screen appearance, notification settings and background delivery still need iPhone acceptance.
